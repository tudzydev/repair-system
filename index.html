คำถามที่ 1.1

จงระบุ User Roles ทั้ง 3 ประเภท และอธิบายสิทธิ์การเข้าถึงข้อมูลของแต่ละบทบาท

  • Admin (ผู้ดูแล): ดูใบแจ้งซ่อมทั้งหมด มอบหมายเจ้าหน้าที่ กำหนดวันเสร็จ ดูสถิติและส่งออกข้อมูลทุกงาน และจัดการบัญชีผู้ใช้ ตัวอย่างโปรเจ็กต์มีรายการและเพิ่มผู้ใช้ ส่วนแก้ไข/ปิดใช้งานบัญชีเป็นแบบฝึกต่อยอด
  • Teacher (ครู/บุคลากร): สร้างใบแจ้งซ่อม แนบภาพก่อนซ่อม ดูสถานะและแสดงความคิดเห็นในงานของตนเอง ดูสถิติ พิมพ์และส่งออกเฉพาะข้อมูลที่ตนมีสิทธิ์
  • Technician (เจ้าหน้าที่ซ่อม): ดูงานที่ได้รับมอบหมาย เริ่มดำเนินการ บันทึกผลซ่อม ค่าใช้จ่ายและวันเสร็จ แนบภาพก่อน–หลังซ่อม และแสดงความคิดเห็นในงานนั้น

ทุกบทบาทต้องเข้าสู่ระบบ ตรวจทั้งบทบาทและสิทธิ์ต่อใบแจ้งซ่อมที่เซิร์ฟเวอร์ การซ่อนปุ่มอย่างเดียวไม่เพียงพอ โดยใบงานไม่ได้ระบุขอบเขตข้อมูลอย่างละเอียด จึงกำหนดขอบเขตข้างต้นเพื่อใช้ในตัวอย่างนี้

คำถามที่ 1.2

จงสกัดคำนาม (Noun Extraction) จากโจทย์ความต้องการด้านบน เพื่อระบุคลาสที่ควรสร้างในระบบ (เช่น RepairRequest, User, Comment) และคำนามที่ไม่ควรสร้างเป็นคลาส พร้อมอธิบายเหตุผล

คำนามที่ควรเป็น Entity Class:

  • User: ผู้ใช้มีรหัส ชื่อ รหัสผ่าน และบทบาทเป็นของตนเอง
  • RepairRequest: ใบแจ้งซ่อมมีเลขอ้างอิง รายละเอียด สถานะ ผู้รับผิดชอบ และพฤติกรรมเปลี่ยนสถานะ
  • RepairImage: รูปแต่ละรูปมีชนิดก่อน/หลังซ่อม path และเวลาอัปโหลด ใบแจ้งซ่อมหนึ่งใบมีได้หลายรูป
  • Comment: ความคิดเห็นมีข้อความ ผู้เขียน เวลา และใบแจ้งซ่อมที่เกี่ยวข้อง

คำนามที่ไม่ต้องเป็น Entity Class แยกในขอบเขตนี้:

  • Building/Room: เก็บเป็น attribute ของใบแจ้งซ่อม หากต้องจัดการรายการอาคาร/ห้องหรือความสัมพันธ์เพิ่มเติมจึงค่อยแยกตาราง
  • Status, ProblemType, Urgency: เป็นชุดค่าจำกัด ใช้ Enum หรือค่าที่ตรวจสอบได้ Enum เป็นคลาส Python ได้ แต่ไม่จำเป็นต้องมีตาราง entity
  • Cost, วันกำหนดเสร็จ และผลซ่อม: เป็นข้อมูลของใบแจ้งซ่อม ยังไม่มีวงจรชีวิตแยก
  • Admin/Teacher/Technician: ใช้ role ใน User เพราะข้อมูลบัญชีเหมือนกัน; Dashboard, CSV และ PDF เป็นหน้าจอหรือบริการนำเสนอข้อมูล ไม่ใช่ entity ในฐานข้อมูล
  • ไฟ แอร์ คอมพิวเตอร์: ในโจทย์นี้เป็นประเภทปัญหา หากต้องติดตามอุปกรณ์รายชิ้นจึงเพิ่มคลาส Asset ในอนาคต

คำถามที่ 2.1

จงเขียน SQL CREATE TABLE สำหรับตาราง repair_requests พร้อมกำหนด Foreign Key Constraints และ CHECK Constraints ใน SQLite

สร้างตาราง users ก่อน และเปิดใช้ Foreign Key ในทุก SQLite connection:

PRAGMA foreign_keys = ON;

CREATE TABLE IF NOT EXISTS repair_requests (
    id INTEGER PRIMARY KEY,
    request_no TEXT NOT NULL UNIQUE,
    user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE RESTRICT,
    building TEXT NOT NULL,
    room TEXT NOT NULL,
    problem_type TEXT NOT NULL CHECK (problem_type IN ('electrical','furniture','computer','aircon','other')),
    description TEXT NOT NULL,
    urgency TEXT NOT NULL DEFAULT 'medium' CHECK (urgency IN ('low','medium','high')),
    status TEXT NOT NULL DEFAULT 'pending' CHECK (status IN ('pending','accepted','in_progress','completed')),
    assigned_to INTEGER REFERENCES users(id) ON DELETE RESTRICT,
    due_date DATE,
    completion_date DATE,
    cost NUMERIC(12,2) CHECK (cost IS NULL OR cost >= 0),
    result TEXT,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

NOT NULL ป้องกันข้อมูลบังคับเป็น NULL เพราะ CHECK เพียงอย่างเดียวยอมให้ NULL ผ่านได้ ใช้ RESTRICT เพื่อเก็บประวัติงานไว้เมื่อมีการอ้างถึงผู้ใช้; FK ตรวจว่าผู้ใช้มีอยู่ แต่บทบาท technician ต้องตรวจในโค้ดเพิ่มเติม

ใบงานเสนอ cost REAL; ตัวอย่างนี้ใช้ NUMERIC(12,2) และ Decimal ใน Python สำหรับจำนวนเงิน แต่ SQLite ไม่บังคับ precision/scale ตามการประกาศ จึงตรวจช่วงและทศนิยมในแอป หากต้องการเก็บเงินอย่างเที่ยงตรงควรใช้ INTEGER หน่วยสตางค์

คำถามที่ 2.2

จงอธิบายความสัมพันธ์ (Relationships) ระหว่างตารางต่างๆ พร้อมระบุ Cardinality (1:1, 1:N, M:N) และอธิบายว่าเหตุใดจึงแยกตาราง repair_images ออกจาก repair_requests

  • users.id → repair_requests.user_id: 1:N ผู้ใช้หนึ่งคนแจ้งได้ 0 ถึงหลายงาน งานแต่ละงานมีผู้แจ้งหนึ่งคน
  • users.id → repair_requests.assigned_to: 1:N เจ้าหน้าที่หนึ่งคนรับได้หลายงาน งานแต่ละงานมีเจ้าหน้าที่ 0 หรือ 1 คนก่อนมอบหมาย
  • repair_requests.id → repair_images.repair_id: 1:N ใบแจ้งซ่อมหนึ่งใบมีภาพ 0 ถึงหลายรูป แต่ละภาพเป็นของงานหนึ่งใบ
  • repair_requests.id → comments.repair_id: 1:N ใบแจ้งซ่อมมีความคิดเห็นได้หลายรายการ
  • users.id → comments.user_id: 1:N ผู้ใช้เขียนความคิดเห็นได้หลายรายการ แต่ละรายการมีผู้เขียนหนึ่งคน

ไม่มีความสัมพันธ์ 1:1 ที่บังคับในโครงสร้างนี้ ผู้ใช้กับงานที่ร่วมแสดงความคิดเห็นมองเชิงแนวคิดเป็น M:N ได้ โดย comments เก็บผู้ใช้และใบแจ้งซ่อมพร้อมข้อความ และคู่เดียวกันแสดงความคิดเห็นได้หลายครั้ง ส่วนการมอบหมายตาม schema ปัจจุบันเป็น 1:N ไม่ใช่หลายเจ้าหน้าที่ต่องาน

แยกรูปออกเป็นหลายแถวเพื่อเก็บหลายภาพโดยไม่ใช้คอลัมน์ image1/image2 หรือ path หลายค่ารวมในช่องเดียว รองรับหลัก 1NF เพิ่ม/ลบรูปและค้นหาภาพก่อน/หลังได้โดยไม่แก้โครงสร้างตาราง ไม่ได้หมายความว่าการเก็บ path เดี่ยวในตารางหลักผิดเสมอ แต่ไม่รองรับจำนวนภาพที่เปลี่ยนแปลงตามโจทย์นี้

คำถามที่ 3.1

จากโค้ดข้างต้น จงอธิบายว่า:

  • หลักการ Encapsulation ถูกนำมาใช้อย่างไรใน Python (เปรียบเทียบกับ PHP)
  • เหตุใดจึงใช้ Optional[int] และ Optional[date] (Nullable Types)
  • @dataclass decorator ช่วยลดโค้ดซ้ำซ้อนอย่างไร
  • Encapsulation: RepairRequest รวมข้อมูลและการเปลี่ยนสถานะผ่าน assign_to/start_repair/complete_repair แต่ attribute ใน dataclass ตัวอย่างยังเป็น public จึงกำหนด status โดยตรงได้ Python ใช้ _name เป็นข้อตกลงว่าเป็นข้อมูลภายใน และ __name ทำ name mangling ซึ่งไม่ใช่การปิดกั้นการเข้าถึงแบบ private ของ PHP หากต้องการควบคุมการเปลี่ยนค่าควรใช้ property และตรวจเงื่อนไขใน method
  • Optional: Optional[int] เท่ากับ int | None และ Optional[date] เท่ากับ date | None เพราะ assigned_to และ due_date ยังไม่มีค่าก่อนมอบหมายงาน Python type hint ใช้ช่วย IDE/static checker และไม่บังคับชนิดตอน runtime โดยอัตโนมัติ ต่างจาก PHP ?int ที่ตรวจชนิดตอน runtime; Optional ไม่ได้หมายถึงละ argument ได้เสมอ ต้องมี default ถ้าต้องการละ argument
  • @dataclass: สร้าง __init__, __repr__ และ __eq__ ตาม field ให้ ลดการเขียน boilerplate และใช้ field(default_factory=datetime.now) เพื่อสร้างเวลาใหม่ต่อ instance แต่ไม่ได้บันทึกฐานข้อมูลหรือ validate ข้อมูลให้เอง

จงเขียน Python Function สำหรับสร้างรหัสใบแจ้งซ่อมอัตโนมัติ (Format: RP-YYYYMM-XXX เช่น RP-202609-001) โดยใช้ datetime และ str.zfill()

def generate_request_no(sequence_number: int, now=None) -> str:
    now = now or datetime.now()
    if not 1 <= sequence_number <= 999:
        raise ValueError("รูปแบบเลข 3 หลักรองรับสูงสุด 999 ใบต่อเดือน")
    return f"RP-{now:%Y%m}-{str(sequence_number).zfill(3)}"
from datetime import datetime
print(generate_request_no(1, datetime(2026, 9, 1)))
# RP-202609-001
print(generate_request_no(25, datetime(2026, 10, 12)))
# RP-202610-025

ฟังก์ชันข้างต้นจัดรูปแบบเลขจาก sequence ที่รับมา ส่วนการสร้างลำดับอัตโนมัติใช้ตาราง RequestCounter แยกรายเดือนและ atomic upsert ต่อไปนี้ แล้ว commit พร้อมใบแจ้งซ่อม เพื่อป้องกันสองคำขอได้เลขเดียวกัน ไม่ใช้ count()+1 เพราะอาจซ้ำเมื่อมีการลบหรือสร้างพร้อมกัน

class RequestCounter(db.Model):
    """ตัวนับรายเดือน อัปเดตแบบ atomic เพื่อป้องกันเลขซ้ำ."""
    __tablename__ = "request_counters"
    month = db.Column(db.String(6), primary_key=True)
    sequence = db.Column(db.Integer, nullable=False)
def next_request_no() -> str:
    now = datetime.now()
    stmt = insert(RequestCounter).values(month=now.strftime("%Y%m"), sequence=1)
    stmt = stmt.on_conflict_do_update(
        index_elements=[RequestCounter.month],
        set_={"sequence": RequestCounter.sequence + 1},
    ).returning(RequestCounter.sequence)
    sequence = db.session.execute(stmt).scalar_one()
    # ตัวนับและใบแจ้งซ่อมจะ commit ใน transaction เดียวกันที่ route
    return generate_request_no(sequence, now)

คำถามที่ 3.3

จงอธิบาย State Transition ของ status ในคลาส RepairRequest ว่าเปลี่ยนจาก pending → accepted → in_progress → completed ได้อย่างไร และเหตุใดจึงต้องมีเงื่อนไขตรวจสอบใน method start_repair() (เปรียบเทียบกับหลักการ State Pattern)

pending → assign_to() → accepted → start_repair() → in_progress → complete_repair() → completed

start_repair ตรวจ accepted เพื่อป้องกันข้ามการรับเรื่องและมอบหมายงาน หรือเริ่มงานที่เสร็จแล้ว แนวคิดตรงกับ State Pattern ที่จำกัดพฤติกรรมตามสถานะ แต่โค้ดนี้เป็น Enum ร่วมกับเงื่อนไข ไม่ใช่ State Pattern เต็มรูปแบบที่แยกสถานะแต่ละชนิดเป็น object

ในโค้ดต้นฉบับ assign_to และ complete_repair ยังไม่มี guard; complete_repair รับ result แต่ไม่ได้เก็บ result หรือวันเสร็จ และ comment เรื่อง repository ยังไม่ใช่การบันทึกจริง โปรเจ็กต์ตัวอย่างเพิ่มการตรวจสถานะและบันทึกค่าดังนี้:

def assign_to(self, technician, due_date):
    if self.status != RequestStatus.PENDING.value:
        raise ValueError("มอบหมายได้เฉพาะงานที่รอรับเรื่อง")
    if technician.role != "technician":
        raise ValueError("ผู้รับงานต้องเป็นเจ้าหน้าที่ซ่อม")
    if due_date < date.today():
        raise ValueError("วันกำหนดเสร็จต้องไม่อยู่ในอดีต")
    self.assigned_to = technician.id
    self.due_date = due_date
    self.status = RequestStatus.ACCEPTED.value

def start_repair(self):
    if self.status != RequestStatus.ACCEPTED.value or self.assigned_to is None:
        raise ValueError("ต้องรับเรื่องและมอบหมายเจ้าหน้าที่ก่อนเริ่มซ่อม")
    self.status = RequestStatus.IN_PROGRESS.value

def complete_repair(self, cost, result):
    if self.status != RequestStatus.IN_PROGRESS.value:
        raise ValueError("ต้องเริ่มดำเนินการก่อนบันทึกผลซ่อม")
    if not cost.is_finite() or cost < 0 or cost > 9999999999.99:
        raise ValueError("ค่าใช้จ่ายต้องเป็นตัวเลขตั้งแต่ 0 ถึง 9,999,999,999.99")
    if not result.strip():
        raise ValueError("กรุณาระบุผลการซ่อม")
    self.cost = cost
    self.result = result.strip()
    self.completion_date = date.today()
    self.status = RequestStatus.COMPLETED.value

method เปลี่ยนค่าบน object ส่วน route ตรวจผู้ใช้และเรียก db.session.commit() เพื่อบันทึกฐานข้อมูล

@app.route("/login", methods=["GET", "POST"])
def login():
    if current_user.is_authenticated:
        return redirect(url_for("dashboard"))
    if request.method == "POST":
        username = request.form.get("username", "").strip()
        user = db.session.scalar(select(User).where(User.username == username))

def roles_required(*roles):
    def decorator(view):
        @wraps(view)
        def wrapped(*args, **kwargs):
            if current_user.role not in roles:
                abort(403)
            return view(*args, **kwargs)
        return wrapped
    return decorator

def visible_repairs():

    stmt = select(RepairRequest)
    if current_user.role == "teacher":

ฟอร์มใช้ multipart/form-data ตั้ง MAX_CONTENT_LENGTH เป็น 5 MB สำหรับข้อมูลรวมต่อ request, secure_filename ตรวจชื่อ, UUID ป้องกันชื่อซ้ำ และ Pillow ตรวจเนื้อหาภาพ ไม่เชื่อเฉพาะนามสกุลหรือ MIME ที่เบราว์เซอร์ส่งมา เก็บภาพนอก static เพื่อให้ route ตรวจสิทธิ์ก่อนส่งไฟล์

def save_image(file) -> str:
    safe_name = secure_filename(file.filename or "")
    extension = Path(safe_name).suffix.lower()
    formats = {".jpg": "JPEG", ".jpeg": "JPEG", ".png": "PNG", ".gif": "GIF"}
    if extension not in formats:
        raise ValueError("อนุญาตเฉพาะไฟล์ JPG, PNG และ GIF")
    try:
        with warnings.catch_warnings():
            warnings.simplefilter("error", Image.DecompressionBombWarning)
            image = Image.open(file.stream)
            if image.format != formats[extension]:
                raise ValueError("เนื้อหาไฟล์ไม่ตรงกับนามสกุลภาพ")
            image.verify()
    except (UnidentifiedImageError, OSError, SyntaxError, Image.DecompressionBombError,
            Image.DecompressionBombWarning) as exc:
        raise ValueError("ไฟล์ภาพไม่ถูกต้องหรือมีขนาดพิกเซลใหญ่เกินไป") from exc
    file.stream.seek(0)
    filename = f"{uuid4().hex}{extension}"
    file.save(Path(current_app.config["UPLOAD_FOLDER"]) / filename)
    return filename

  for (const [category, message] of messages) {
    const icon = ['success', 'error', 'warning', 'info', 'question'].includes(category) ? category : 'info';
    await Swal.fire({ title: icon === 'success' ? 'สำเร็จ' : 'แจ้งเตือน', text: message, icon, confirmButtonText: 'ตกลง' });
  }
})();

ใช้ text แสดงข้อความและ tojson แทนการนำข้อความต่อเข้า JavaScript โดยตรง ถ้า CDN โหลดไม่ได้ยังเห็นข้อความในหน้าเว็บ

@app.get("/export/csv")
@login_required
def export_csv():
    def safe_cell(value):
        text = "" if value is None else str(value)
        return "'" + text if text.lstrip().startswith(("=", "+", "-", "@")) else text
    stream = StringIO(newline="")
    writer = csv.writer(stream)
    writer.writerow(["เลขใบแจ้งซ่อม", "อาคาร", "ห้อง", "ปัญหา", "สถานะ", "ค่าใช้จ่าย", "รายละเอียด"])
    for r in db.session.scalars(filtered_repairs()):
        writer.writerow([safe_cell(value) for value in
                         (r.request_no, r.building, r.room, PROBLEM_TYPES[r.problem_type],
                          STATUSES[r.status], r.cost, r.description)])
    return Response("\ufeff" + stream.getvalue(), content_type="text/csv; charset=utf-8",
                    headers={"Content-Disposition": "attachment; filename=repairs.csv"})

@login_required

    repair = accessible_repair(repair_id)
    try:
        from weasyprint import HTML
    except (ImportError, OSError):
        flash("ยังไม่ได้ติดตั้ง WeasyPrint/Pango ใช้ปุ่มพิมพ์และ Save as PDF ได้", "info")

    # Template ไม่มี external assets จึงไม่ต้อง fetch URL จากข้อมูลผู้ใช้

                    headers={"Content-Disposition": f"attachment; filename={repair.request_no}.pdf"})

🔍 ข้อสงสัยที่พบบ่อย (Frequently Asked Questions)

รวมคำถามที่นักศึกษามักสงสัยในการวิเคราะห์และออกแบบระบบแจ้งซ่อมโรงเรียน (Python Edition) พร้อมแนวคำตอบเพื่อทบทวนความเข้าใจ

❓ Q1: ทำไมต้องใช้ Enum class สำหรับ RequestStatus และ ProblemType แทนการใช้ string ธรรมดา?
แนวคำตอบ: การใช้ Enum จาก module enum มีข้อดีหลายประการ:
  • Type Safety: กำหนดชุดค่าชัดเจน IDE/static checker ช่วยตรวจได้ และ RequestStatus("pendding") จะเกิด ValueError; การใส่ type hint เพียงอย่างเดียวไม่ตรวจ runtime อัตโนมัติ
  • Autocomplete: VS Code / PyCharm จะแนะนำค่าที่เป็นไปได้ทั้งหมด
  • Refactoring ง่าย: เครื่องมือ IDE ช่วยเปลี่ยนชื่อสมาชิกที่อ้างอิงได้ แต่ string ที่เก็บในฐานข้อมูลหรือ API ต้องวางแผน migration แยก
  • Self-documenting: โค้ดอ่านเข้าใจได้เองว่าระบบมีสถานะอะไรบ้าง
  • SQLite CHECK: ใช้คู่กับ CHECK IN (...) ในฐานข้อมูลได้
❓ Q2: ทำไมต้องแยกตาราง repair_images ออกจาก repair_requests? เก็บเป็น path ในตารางหลักเลยไม่ได้หรือ?
แนวคำตอบ: การแยกตารางเป็นหลักการ Normalization (1NF) เพราะ:
  • 1 ใบแจ้งซ่อม มีหลายรูป: ความสัมพันธ์เป็น 1:N (อาจมีรูปก่อนซ่อม 2 รูป, หลังซ่อม 3 รูป)
  • ยืดหยุ่น: เพิ่มรูปได้ไม่จำกัด ไม่ต้องแก้โครงสร้างตาราง
  • Query ง่าย: SELECT * FROM repair_images WHERE repair_id = ?
  • ถ้าเก็บในตารางหลัก: ต้องสร้างคอลัมน์ image1, image2, image3... ซึ่งไม่ยืดหยุ่นและเสียพื้นที่
❓ Q3: ในโค้ด Python มี Optional[int] และ Optional[date] มันคืออะไร? ต่างจาก PHP ?int อย่างไร?
แนวคำตอบ: Optional[X] จาก module typing หมายความว่า ตัวแปรนั้นสามารถรับค่าเป็น type X หรือ ค่า None ก็ได้ (เทียบเท่า X | None ใน Python 3.10+)
  • PHP: ?int (Nullable Types) - ตรวจสอบตอน Runtime เท่านั้น
  • Python: Optional[int] - เป็น Type Hint สำหรับ Static Type Checker (mypy) และ IDE
  • มักใช้กับ Attribute ที่ "อาจจะยังไม่มีค่า" ในช่วงแรก เช่น assigned_to, due_date, cost
❓ Q4: @dataclass decorator คืออะไร? ทำไมต้องใช้?
แนวคำตอบ: @dataclass (Python 3.7+) เป็น decorator ที่สร้าง __init__, __repr__, __eq__ ให้อัตโนมัติจาก class attributes
  • ลด Boilerplate: ไม่ต้องเขียน __init__ เอง (เทียบเท่า Constructor Promotion ใน PHP 8)
  • อ่านง่าย: เห็นโครงสร้างข้อมูลได้ชัดเจนในบรรทัดเดียว
  • Immutable ได้: ใช้ @dataclass(frozen=True) สำหรับ immutable objects
  • เหมาะกับ Model: ใช้แทน ORM Model ในกรณีที่ไม่ต้องการความซับซ้อน
❓ Q5: การอัปโหลดรูปภาพใน Flask ต้องระวังเรื่องความปลอดภัยอะไรบ้าง?
แนวคำตอบ: การอัปโหลดไฟล์เป็นจุดเสี่ยงสำคัญ ต้องตรวจสอบดังนี้:
  • ใช้ secure_filename(): จาก werkzeug.utils เพื่อจัดการชื่อไฟล์เพื่อลดความเสี่ยง Path Traversal แต่ไม่ตรวจเนื้อหาหรือสิทธิ์
  • ตรวจสอบ MIME type: ใช้ python-magic ไม่ใช่แค่ request.files[].mimetype (ปลอมแปลงได้)
  • จำกัดขนาดไฟล์: ตั้งค่า app.config['MAX_CONTENT_LENGTH'] = 5 * 1024 * 1024 (จำกัดข้อมูลรวมต่อ request ไม่ใช่เฉพาะไฟล์เดียว)
  • เปลี่ยนชื่อไฟล์: ใช้ UUID หรือ timestamp แทนชื่อเดิม
  • จำกัดนามสกุล: อนุญาตเฉพาะ .jpg, .jpeg, .png, .gif
❓ Q6: ทำไมต้องใช้ SweetAlert2 แทน alert() ของ JavaScript?
แนวคำตอบ: SweetAlert2 มีข้อดีกว่ามาก:
  • สวยงาม: UI ทันสมัย ปรับแต่งสี/ไอคอนได้
  • Responsive: ใช้งานได้ทั้ง Desktop และ Mobile
  • Promise-based: ใช้ async/await ได้ ทำให้จัดการ Flow ง่าย
  • มีหลายประเภท: success, error, warning, info, question
  • UX ดีกว่า: alert() ดั้งเดิมจะ block thread และดูเก่า
❓ Q7: การสร้าง PDF ใน Python ต้องใช้ Library อะไร?
แนวคำตอบ: มีหลายตัวเลือกตามความเหมาะสม:
  • WeasyPrint: แปลง HTML+CSS เป็น PDF (แนะนำสำหรับใบงานนี้ เพราะใช้ Jinja2 template เดิม)
  • pdfkit (wkhtmltopdf): ต้องติดตั้ง wkhtmltopdf แยก
  • ReportLab: สร้าง PDF จากโค้ด Python โดยตรง (เหมาะสำหรับรายงานซับซ้อน)
  • FPDF / fpdf2: เบา ง่าย เหมาะกับเอกสารไม่ซับซ้อน
  • Browser Print: ใช้ CSS @media print + window.print() (ง่ายที่สุด)
❓ Q8: Flask vs Django ต่างกันอย่างไร? ทำไมใบงานนี้เลือก Flask?
แนวคำตอบ:
  • Flask (Microframework): เล็ก ยืดหยุ่น เลือก Library เอง (SQLAlchemy, Flask-Login, Jinja2) เหมาะกับการเรียนรู้โครงสร้าง
  • Django (Full-stack): มีองค์ประกอบหลักพร้อม เช่น Admin, Auth และ ORM มีแนวทางและโครงสร้างมาตรฐานให้ใช้ แต่ยังปรับแต่งและเลือกวิธีพัฒนาได้
  • เหตุผลที่เลือก Flask: นักศึกษาจะได้เรียนรู้การประกอบชิ้นส่วนเอง (DIY) เพื่อฝึกเข้าใจสถาปัตยกรรมเว็บจากส่วนประกอบต่าง ๆ และเหมาะกับขอบเขตของใบงาน
